# 修复文件浏览器多选审查问题

## Goal

修复 PR #259 文件浏览器批量操作中的两个高风险缺陷，保证重命名后的选择状态与实际路径一致，并保证 Windows 大小写不敏感文件系统不会绕过移动祖先目录保护。

## Background and confirmed facts

- PR #259 的前端批量键盘操作从 `useFileExplorerStore.getState().selectedEntries` 读取目标。
- `renameEntry` 在 `file_rename` 成功后刷新目录和编辑器状态，但没有同步 `selectedEntries`，因此选中项会保留旧路径。
- Rust `move_path` 在 `prepare_target` 删除覆盖目标前，用 `Path::starts_with` 判断目标是否为源路径祖先；该方法按字符串组件大小写比较，Windows 文件系统语义却不区分大小写。
- 用户已确认修复范围为上述前两项；第三项“符号链接重命名”不在本任务范围内。
- 变更记录版本固定为 `V1.4.0`。

## Requirements

### R1. 重命名后同步文件选择状态

`renameEntry` 成功重命名后，若被重命名条目存在于 `selectedEntries`，必须将其更新为新的相对路径和名称，并保留条目类型及其他元数据。不得在 IPC 失败时提前改变选择状态。相关批量快捷键不得再使用已失效的旧路径。

### R2. 祖先目录判断遵循运行平台路径语义

`move_path` 必须在任何覆盖目标删除前，使用与实际文件系统一致的路径组件比较：原生 Windows 路径不区分大小写，WSL/POSIX 路径保持大小写敏感。必须继续保留现有的根目录、自身目标和子目录移动保护，不改变 Tauri 命令签名或错误契约。

### R3. 回归覆盖

- 前端测试覆盖“选中条目重命名成功后选择项更新”，并确认失败时选择项不变。
- Rust 测试覆盖 Windows 大小写不同但实际相同的祖先目标，确认移动拒绝且覆盖目标及源内容均保留；同时保留 POSIX/WSL 大小写敏感语义的单元覆盖（可用纯路径比较测试）。

### R4. 交付记录

在 `CHANGELOG.md` 的 `V1.4.0` 部分记录修复，并在 `docs/功能清单.md` 的文件浏览器板块记录选择状态和移动安全修复。

## Acceptance Criteria

- [ ] 重命名成功后，选中项指向新路径；重命名失败时仍指向原路径。
- [ ] Windows 上对大小写不同的实际同一路径执行覆盖移动时，在删除目标前返回祖先保护错误，源和目标数据均未丢失。
- [ ] WSL/POSIX 大小写敏感路径不会被错误折叠为 Windows 语义；现有同路径、目标在源目录内和根目录保护不回归。
- [ ] 前端定向测试、Rust 文件命令测试、TypeScript 检查、生产构建和严格架构检查通过。
- [ ] `CHANGELOG.md` 与 `docs/功能清单.md` 均使用 `V1.4.0`，未引入 `TEMP` 或其他版本号。

## Out of scope

- 不修复 PR 审查第三项符号链接重命名问题。
- 不新增 IPC 命令、修改现有参数、调整数据库/持久化协议或重构文件浏览器批量操作架构。
- 不启动 Tauri 应用或服务进行 AI 运行时 UI 验证；人工验证项仅在交付说明中列出。
